# LaTeX Page Locate

把頁碼從「寫上去的」變成「查出來的」。

## 為什麼需要這個 skill

勘誤表的 `location: p.29` 是**學生唯一的導航資訊**——他拿手上那本翻到第 29 頁照著改。
頁碼錯，那條勘誤就整條失效，而且失效方式是靜默的：檔案格式正確、表格照樣生成、
網站照樣顯示，只有學生翻到那頁時發現找不到東西。

典型的既有驗證只驗**格式**（`p.29` 像不像頁碼），不驗**正確性**（那段文字在不在
第 29 頁）。這個 skill 補的就是後者。

另一個常被忽略的來源：**講義重排會讓頁碼整批位移**。加一段話、換一張圖、改一個
`\needspace`，後面所有頁碼都可能往後推。既有的 `location` 不會自己更新。

## Trigger

用戶說：

- 「這段在第幾頁」「幫我查頁碼」「頁碼是多少」
- 「頁碼對不對」「核一下頁碼」「這條勘誤指到哪一頁」
- 「勘誤要填 location」「errata 的頁碼」
- 改完講義後問「頁碼有沒有跑掉」

或**任何要寫 `location:` 欄位的時候**——寫之前先查，不要先寫再說。

## 兩種模式

### 模式 A：locate（文字 → 頁碼）

寫新勘誤時用。給一段原文，回答它印在第幾頁。

### 模式 B：verify（文字 + 宣稱頁碼 → 通過／不通過）

稽核既有勘誤時用。給 `(original, claimed_page)`，回答那段文字是不是真的在該頁；
不是的話回報實際頁碼。

批次跑模式 B 就是「把整份 errata.yaml 的頁碼掃一遍」。

## 流程

### Step 0：確認 PDF 是新的

頁碼來自 PDF，不是 source。**source 改過而沒重編，查出來的是舊頁碼**——這是最容易
踩的坑，因為它看起來完全正常。

```
若 .tex 的 mtime 比 .pdf 新 → 先 compile_latex，不要直接查
```

沒有 `project_path` / `main_file` 就問清楚，或從 cwd 推斷。

### Step 1：縮小範圍，不要逐頁掃

`get_page_content` 一次抽一頁。一本 200 頁的合訂本逐頁抽是 200 次 call。

先用 `analyze_pages` 或 `find_pagebreaks` 拿到章節 → 頁碼的對應，把候選範圍縮到
該章節的那幾頁，再逐頁 `get_page_content` 比對。

勘誤條目通常有 `chapter:` 欄位（如 `ch02 §3`），那就是縮小範圍的線索。

### Step 2：比對文字

抽出頁面文字後，用**正規化後的子字串比對**，不要用完全相等：

- PDF 抽出的文字會有斷行、連字、空白差異
- 中文之間的空白不穩定
- 填空題的底線、數學式在抽取時形狀會變

建議先各自去掉所有空白字元再比對；仍找不到時，取原文最長的連續中文片段（略過
數學式與 `\command`）當關鍵字再試一次。

### Step 3：回報

**locate 模式**回報：

- 頁碼
- 命中的那一段前後文（讓人確認找對地方）
- 若跨頁：起訖頁碼，寫成 `p.139--141`

**verify 模式**回報：

- 通過／不通過
- 不通過時給**實際頁碼**，不要只說「錯了」

### Step 4：跨頁與多處

- 一段文字橫跨兩頁 → `p.139--141`（範圍）
- 同一筆勘誤有多處要改 → `p.115、p.119、p.121`（頓號並列）

這兩種寫法都是 errata schema 接受的格式。

## ⚠ 平面化的交付版抽不到文字

參考解答等交付物會加浮水印並**平面化**（見 educator 的 `release-record.md`）。
平面化之後整頁是一張圖，`get_page_content` 與 `pdftotext` 都抽不到任何文字。

遇到這種 PDF：

1. **改查編譯用的未平面化 PDF**（首選）——內容相同，頁碼一致
2. 真的只有平面化版時，用 `preview_page` render 成 PNG 直接看

**不要因為抽不到文字就回報「找不到」**——那會被讀成「這段話不在這份文件裡」，
與事實相反。要明講是平面化導致抽不到。

## ⚠ 頁碼以哪一版為準

勘誤的 `location` **以學生手上那一版為準**，不是最新版——他是拿舊版在對照。

所以查頁碼時要確認查的是**發放當時**的那份 PDF。`release.yaml` 記著每次發放的
`commit`，必要時用 `compile_diff(git_ref)` 或 checkout 該 commit 重編。

拿最新版的頁碼填進舊版的勘誤，是這個 skill 最容易製造的新錯誤。

## 誠實邊界

- **查不到就說查不到。** 不要退回「憑章節推估」——推估出來的數字看起來跟查出來的
  一模一樣，但沒有依據。留空或標成待確認，人看得出來；錯的數字看不出來。
- **這些 tool 不在當前 session 時**（MCP 沒連上，只看得到 `latex-*` 那幾個 skill），
  同樣不要憑印象填，先說明工具沒接上。

## 串接的 tools

| Tool | 在這裡的用途 |
|---|---|
| `analyze_pages` / `find_pagebreaks` | 章節 → 頁碼，縮小搜尋範圍 |
| `get_page_content` | 抽單頁文字，做實際比對 |
| `extract_blocks` | 需要 bbox 判斷跨頁邊界時 |
| `compile_latex` | PDF 比 source 舊時先重編 |
| `preview_page` | 平面化 PDF 只能用看的 |
| `get_document_info` | 總頁數，判斷宣稱頁碼有沒有超出範圍 |

> 實際參數名以 MCP 回傳的 tool schema 為準（既有 skill 的慣例是 `project_path` +
> `main_file`）。不要憑本文件硬編參數。
